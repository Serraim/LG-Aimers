# 야구 분석 지표 → 우리 데이터 대응표

> **전부 가설이다. 하나도 검증 안 됐다.**
> 이 문서는 "만들 수 있는 것"의 목록이지 "만들면 오르는 것"의 목록이 아니다.
> 실제 측정 전에는 어떤 것도 확정하지 않는다.

우리 target 은 `control_success` = **"의도한 곳에 갔는가"** 다 (B묶음에서 확인).
따라서 **실점 계열 지표(ERA, WHIP, FIP)는 직접 관련이 약하다.**
관련 있는 것은 **제구·커맨드·메카닉·워크로드** 계열이다.

---

## A. 결과 계열 — 대부분 못 쓰거나 약함

| 지표 | 뜻 | 우리 데이터 | 판단 |
|---|---|---|---|
| ERA / WHIP / FIP / xFIP / SIERA | 실점 억제력 | 없음 | **관련 약함.** 제구가 아니라 결과 |
| **BB%, BB/9** | 볼넷 비율. 제구의 고전 지표 | 볼넷 컬럼 없음 | `balls_before==3` 빈도가 대리 지표 |
| K/BB | 삼진/볼넷 | 없음 | 못 씀 |
| OPS, wOBA (타자) | 타자 생산력 | `asof_batter_success_rate` 만 있음 | **간접.** 아래 F 참고 |

**ERA 계열이 왜 약한가:** 한가운데 몰린 공(제구 실패)이 안타가 안 되면 ERA 는 좋다.
우리 target 은 결과가 아니라 **의도 달성**이다.

---

## B. 제구·커맨드 전용 지표

| 지표 | 뜻 | 우리 데이터 | 상태 |
|---|---|---|---|
| **Zone%** | 스트라이크존 통과 비율 | `asof_pitcher_strike_rate` | **이미 있음** |
| **Meatball%** | 한가운데로 몰린 비율 | `asof_pitcher_middle_rate` | **이미 있음** |
| **F-Strike%** | 초구 스트라이크 비율 | `balls=0 & strikes=0` 행에서 계산 가능 | 미시도 |
| Edge% | 존 가장자리 공략 비율 | **위치 데이터 없음** | **불가** |
| CSW% | 헛스윙+루킹 스트라이크 | 없음 | 불가 |
| Location+ / Command+ | 목표 대비 실제 위치 오차 | **위치 데이터 없음** | **불가** |
| 터널링 | 구종 간 초기 궤적 일치 | 위치 필요 | 불가 |

> **구조적 제약:** `trackman_history.csv` 30컬럼에 **plate_x / plate_z 가 없다.**
> 릴리스 지점과 무브먼트만 있고 **공이 최종적으로 어디 갔는지가 없다.**
> 그래서 업계 표준 커맨드 지표는 대부분 만들 수 없다.

## C. 메카닉 일관성 — ★ 가장 유망해 보이는 미탐색 구역

**업계에서 "제구가 좋다"의 물리적 대리 지표는 릴리스 일관성이다.**
매번 같은 지점에서 같은 각도로 놓는 투수가 제구가 좋다.

| 지표 | 재료 | 우리 상태 |
|---|---|---|
| **릴리스 높이 편차** | `rel_height` 의 std | 뽑았으나 **투수당 값 하나** |
| **릴리스 좌우 편차** | `rel_side` 의 std | 뽑았으나 **투수당 값 하나** |
| 익스텐션 | `extension` | 평균만 |
| 구속 편차 | `rel_speed` 의 std | 평균/최대/std 뽑음 |

### 문제점

```
지금        투수의 모든 구종을 섞어서 std 하나
현실        직구 릴리스와 커브 릴리스는 원래 다르다
            그 차이가 std 를 부풀려서 진짜 신호를 덮는다
```

### 가설 (미검증)

```
구종별로 나눈 릴리스 편차가 제구와 더 강하게 연결될 것이다
  tmp_relheight_std_fastball
  tmp_relheight_std_breaking
  tmp_relside_std_fastball
  ...
```

**trackman 에 `pitch_type_group` 이 있으므로 계산 가능하다.**
단 **한 번 실패한 적이 있다** (trackman 프로필 11개 추가 → -11.04).
그때는 투수당 고정값이었고 기존 `asof_*` 와 정보가 겹쳤다는 해석이었다.
**구종별로 쪼개도 같은 이유로 실패할 수 있다.**

## D. 워크로드 · 피로 — ★ 새 축

| 지표 | 뜻 | 우리 데이터 |
|---|---|---|
| **시즌 누적 투구수** | 이번 시즌 얼마나 던졌나 | **`asof_pitcher_n` 복원으로 가능** |
| P/GS | 경기당 투구수 | 다른 행 필요. **불가** |
| 휴식일 | 등판 간격 | 다른 행 필요. **불가** |
| 이닝 내 피로 | 오늘 몇 구째 | 다른 행 필요. **불가** |
| TTO 페널티 | 타순 몇 바퀴째 | `tto` 만들었으나 중요도 꼴찌 |

### 복원 방법 (08-13 공식 허용)

```
표에 저장   각 투수의 학습 기간 말(2024) 누적 투구수와 누적 성공수
2025 행     season_n    = asof_pitcher_n - 저장 누적수
            season_succ = asof_n * asof_success_rate - 저장 성공수
            season_rate = season_succ / season_n
```

**시간축의 빈 구멍을 메운다.**

```
asof_*     통산 6년 누적
recent_*   최근 1/3/5 경기
비어 있음  이번 시즌 전체       <- 여기
```

**reverse / middle / ball / strike 도 같은 방식으로 복원 가능하다.**

### 주의

```
경계값 주의   season_n 이 0 이거나 음수가 되는 행 (신인, 반올림)
표본 주의     시즌 초에는 season_n 이 작아 비율이 불안정 -> 수축 필요
겹침 주의     recent_* 와 정보가 겹칠 수 있다 (규칙 8)
```

## E. 구종 지표

| 지표 | 우리 데이터 | 상태 |
|---|---|---|
| 구종 구성 비율 | `asof_pitcher_fastball/breaking/offspeed_rate` | **이미 있음** |
| 구속 / 회전 / 무브먼트 | trackman | 투수 평균만 씀 |
| Stuff+ | 위 셋의 합성 | 미시도 |
| **구종 × 볼카운트 성향** | trackman 투구별 + 볼카운트 | **미탐색** |
| 구종별 제구 차이 | 구종 × target | **미탐색** |

### 실측된 사실

```
3볼 0스트  ->  빠른공 82.2%
0볼 2스트  ->  빠른공 43.9%
```

**볼카운트가 구종을 거의 결정한다.** 그런데 볼카운트의 성공률 직접 효과는 2.5%p 뿐이다.

### 가설 (미검증)

```
두 효과가 상쇄되고 있을 수 있다
  볼카운트 -> 구종 -> 제구 난이도
지금 컬럼엔 "이 투수의 전체 구종 비율" 만 있고
"이 투수가 이 볼카운트에서 뭘 던지나" 가 없다
```

**이것이 유일하게 투구마다 변하는 trackman 피처가 된다.**
지금까지 만든 trackman 피처는 전부 투수당 고정값이었다.

## F. 매치업

| 지표 | 우리 데이터 | 상태 |
|---|---|---|
| 좌우 스플릿 | `pitcher_hand`, `batter_hand` | `hand_matchup`, `same_hand` 있음 |
| 투수별 개인 스플릿 | 조회표 | **시도했다가 실패** (`m_C` 0점, 이후 +0.60) |
| 타자 규율 (O-Swing 등) | 없음 | 불가 |
| 타자 수준 | `asof_batter_success_rate` | 있음 |

### 가설 (미검증)

```
좋은 타자를 만나면 투수가 더 어려운 곳을 노린다
  -> 의도 자체가 어려워짐
  -> 성공률 하락
```

**`asof_batter_success_rate` 가 낮다 = 그 타자 상대로 투수들이 자주 실패했다.**
좋은 타자일 수도 있고, 그 타자를 상대한 투수들이 나빴을 수도 있다. **구분 안 됨.**

### 타자 trackman 매핑 (08-12 허용, 미탐색)

```
batter_trackman_id 를 연결하면
"이 타자에게 어떤 공이 오는가" 를 집계할 수 있다
  -> 투수의 의도 난이도 대리 지표가 될 수 있다
```

**우리는 투수만 연결했다 (1,456쌍, 92.5%). 타자는 손도 안 댔다.**

## G. 상황 지표

| 지표 | 우리 데이터 | 상태 |
|---|---|---|
| LI (레버리지) | `li` | D묶음. **아직 안 읽음** |
| 승리확률 | `home_win_expectancy`, `away_win_expectancy` | D묶음. 안 읽음 |
| Close and Late | 이닝 + 점수차로 파생 가능 | 미시도 |

**C묶음에서 점수차·주자는 투수를 고정하면 대부분 사라졌다.**
`li` 가 이미 그 정보를 요약하고 있을 가능성이 높다 (규칙 8 확인 대상).

## 정리 — 만들 수 있는 것 우선순위 (전부 가설)

| 순위 | 항목 | 분류 | 근거 강도 | 비용 |
|---|---|---|---|---|
| 1 | 시즌 워크로드 복원 | D | 공식 허용 명시 + 시간축 구멍 확인 | 낮음 |
| 2 | 구종별 릴리스 일관성 | C | 업계 표준 지표. 단 유사 실패 전례 | 중간 |

| 4 | 타자 trackman 매핑 | F | 허용 확인. 완전 미탐색 | 높음 |
| 5 | LUPI 증류 | - | 허용 확인. 92.5% 커버 | 높음 |
| - | F-Strike% | B | 기존 컬럼과 겹칠 가능성 큼 | 낮음 |
| - | Stuff+ 합성 | E | 재료는 이미 넣어봤고 실패 | 낮음 |

**1번부터 하는 이유는 "제일 좋아서"가 아니라 "근거가 제일 단단하고 싸서"다.**
